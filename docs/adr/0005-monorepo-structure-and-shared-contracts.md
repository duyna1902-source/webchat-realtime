# Cấu trúc Monorepo và Hợp đồng Dữ liệu dùng chung

Hệ thống bao gồm ứng dụng web frontend và backend thời gian thực cần chia sẻ định dạng dữ liệu (DTO), enum và sự kiện Socket.io để đảm bảo an toàn kiểu dữ liệu (type-safety). Chúng tôi quyết định tổ chức dự án dưới dạng Monorepo với 3 phân vùng: `client/`, `server/`, và `shared/`.

## Status
accepted

## Considered Options
- **Hai repository độc lập (Polyrepo)**: Frontend và backend nằm ở 2 repo riêng. Bị từ chối vì việc đồng bộ các thay đổi về kiểu dữ liệu (DTO, Socket events) rất dễ bị lệch phiên bản và phát sinh lỗi runtime.
- **Monorepo (Được chọn)**: Toàn bộ code nằm trong một repository; thư mục `shared/` chứa các interface và enum dùng chung được cả client và server import trực tiếp.

## Consequences
- Đảm bảo tính toàn vẹn 100% về type giữa frontend và backend khi phát triển.
- Dễ dàng thiết lập CI/CD: một lệnh `npm run build` ở gốc repo build lần lượt `shared`, `server` và `client`. Ban đầu dự kiến Vercel trỏ vào thư mục `client` và Render trỏ vào thư mục `server`; từ [ADR 0010](./0010-single-host-render-with-session-cookie.md), chỉ còn Render build toàn bộ monorepo và phục vụ cả SPA lẫn API.
- **Phát triển đọc `shared` từ mã nguồn, chỉ production dùng bản build.** Trong phát triển, khi chạy test và khi chạy các lệnh vận hành (data upgrade, thu hồi Session), mọi nơi dùng `@webchat/shared` đều đọc thẳng mã nguồn TypeScript trong `shared/src/`; chỉ bản build production (`npm run build`) và server production (`node dist/index.js`) dùng bản build `shared/dist/`. Client và các test runner vẫn dùng alias trỏ vào mã nguồn như trước. Server tham gia qua export condition `@webchat/source` trong `exports` của `shared/package.json`: condition này đứng trước `types`, `import` và `default`, và mọi script server chạy qua `tsx` đều truyền `--conditions=@webchat/source` (`npm test` kiểm tra điều này và nêu tên script thiếu). Tên condition có tiền tố riêng của dự án vì cờ `--conditions` của Node áp dụng cho mọi package trong tiến trình; một tên chung như `development` hay `source` sẽ chuyển cả các thư viện bên thứ ba sang bản phát triển của chúng. Mapping `paths` cho `@webchat/shared` trong `server/tsconfig.json` (trỏ vào `../shared/dist/index.d.ts`) đã bị bỏ: `tsx` áp dụng mapping này trước export condition, nên hễ `shared/dist/` tồn tại là server phát triển chạy bản build thay vì mã nguồn, và lỗi chỉ lộ ra trên máy chưa từng build. TypeScript giờ tìm kiểu qua export `types` của package. Hook `postinstall` ở gốc repo vẫn build `shared` một lần khi `npm install`, chỉ để editor hiển thị kiểu cho các import `@webchat/shared` trong server; ứng dụng không phụ thuộc vào bước này, và nếu hook bị bỏ qua thì chỉ thiếu kiểu trong editor. Phương án tự động build `shared` trước khi chạy dev, kèm một tiến trình watcher (`tsc -w`), bị từ chối vì: bản build có thể cũ so với mã nguồn mà không ai nhận ra; watcher chạy đua với bộ tự nạp lại của `tsx watch`, nên server có thể nạp lại giữa lúc bản build đang được ghi; nó thêm một tiến trình vào đầu ra dev; và nó hỏng khi cài đặt với lifecycle script bị tắt (`--ignore-scripts`). Quyết định này dễ đảo ngược nên không cần ADR riêng.
